# Physical flood-management asset registry

Generated by `assets_registry.py build`. Founder priority (verbatim, 2026-09-27):
"ข้อมูลจากภาครัฐเชื่อมได้ทั้งหมด ให้เน้นข้อมูลที่เชื่อถือได้ โดยเฉพาะตำแหน่งก่อน" (all
government-source data is connectable; emphasize reliable data, coordinates first)
then "แล้วค่อยวางระบบเรื่องข้อมูลอัพเดท" (then design the update-freshness system). This
is the first pass: ONE registry of physical flood-management assets with coordinates,
each row traceable to an official source. No geocoding, no OSM, no guessed
coordinates anywhere in this file or `assets_registry.py`.

Schema/vocabulary reference: `sources/assets_registry.yaml`. Storage: the `assets` +
`assets_log` tables in `store.py` (append-only addition to that module).

## HII dams and watergates (official, 2026-09-27 snapshot)

Founder priority for this check: "เอาพิกัดจากเว็บไซต์รัฐมีเยอะ" (there's a lot of coordinate
data on government websites already -- go get it). Inputs already downloaded to
`raw/knowledge/api_census/hii/dam.json` and `raw/knowledge/api_census/hii/
watergate_load.json` (HII/thaiwater.net), archived per this repo's per-run convention
to `raw/live/hii_dam/<ISO-timestamp>.json` and `raw/live/hii_watergate/<ISO-
timestamp>.json` (both gitignored under `raw/`, originals never modified). Two new
harvesters, `harvest_hii_dam`/`harvest_hii_watergate` in `assets_registry.py`.

**Field mapping used** (read from the real payloads, not assumed):
- `hii_dam`: `data.{dam_hourly,dam_daily,dam_medium,dam_small_tele}[]` -- each record's
  `dam` sub-object carries `dam_name.th`/`smalldam_name.th`, `dam_lat`/`dam_long` (or
  `tele_station_lat`/`tele_station_long` for `dam_small_tele`), and its own stable
  `id` (used as the asset code -- NOT the outer per-reading `id`, which is a fresh
  measurement-record id every poll). `agency.agency_name`, `geocode.province_name.th`,
  `basin.basin_name.th` at the record's top level.
- `hii_watergate`: `watergate_data.data[]` -- each record's `station` sub-object
  carries `tele_station_name.th`, `tele_station_lat`/`tele_station_long`,
  `tele_station_oldcode`, and its own `id`. `agency`/`geocode`/`basin` at the record's
  top level, same shape as `hii_dam`. The file's sibling top-level `station`/
  `province` lists are reference lookups only, not iterated (each `watergate_data`
  row already embeds everything needed).

**35 of 35 RID dams got coordinates** from `hii_dam` via `_normalize_dam_name`
matching (strip "เขื่อน"/"อ่างเก็บน้ำ"/"คลอง" + the thanthakhat mark + whitespace, then

**Gate dedup**: of 2,176 real HII watergate rows classified `gate` (2,032 after
excluding pump_station/weir), only **3** matched an existing BMA gate row (exact Thai
name + <=0.5 km) and were merged into the existing row (noted, not duplicated); the
remaining 2,032 became new rows. This is a real finding, not a bug: HII's nationwide
watergate naming does not match BMA's own canal/gate naming convention, so name-based
dedup mostly can't find a pair even where the same physical structure might exist in
both feeds.

**Data-quality findings in the source itself** (never silently accepted or corrected,
per this repo's no-geocoding rule):
- `tele_station_oldcode` "E21" is reused by TWO different stations from two different
  agencies (a RID river gauge on the Chi river, and a BMA gate in Lat Krabang, ~370 km
  apart). The asset code is keyed on the feed's own unique `station.id` instead of the
  oldcode, so both survive as distinct rows (a naive oldcode-keyed asset_id would have
  silently collapsed one onto the other via upsert).
- 139 of 2,315 `watergate_data` rows have `station.id == 0` with no name, no oldcode,
  and no coordinate at all -- placeholder/incomplete census entries, skipped entirely
  (not stored as a fake asset).
- Station `BKK007` reports `tele_station_lat`/`long` = `(0, 0)` -- a sentinel, not a
  real point in the Gulf of Guinea -- downgraded to OPEN.
- Station `TN.10` (บ้านนาสา เวียงสา, Nan province) reports `tele_station_lat =
  118.58928` -- a clear decimal-place error in HII's own feed (Nan province is
  ~18.6N, not 118.6N) -- downgraded to OPEN rather than "corrected" to the plausible
  value. Both anomalies are caught by a new `_valid_th_coord` guard (rejects `None`,
  `(0,0)`, and anything outside `THAILAND_BBOX` = 5.5-20.6N/97.3-105.7E) applied in
  both new harvesters.

## Re-running

```
python3 assets_registry.py build
python3 assets_registry.py list --class gate
python3 assets_registry.py near 13.758235 100.676084 --km 3
python3 assets_registry.py stats
```

`build` is idempotent (`INSERT ... ON CONFLICT DO UPDATE` by `asset_id`, never
deletes a row) and only reads from the local `raw/live/*`/`raw/gapfill/*` caches --
no network call is made when the cache is fresher than 6 hours (true for every source
at the time of this build).
