## ขอบเขตข้อมูล (VERIFIED, จาก FloodgateInfo response, ดึง 2026-09-27)
- **67 สถานี/ประตูระบายน้ำ** จัดกลุ่มเป็น **29 หน่วยงาน** ซึ่งทุกชื่อกลุ่มตรงกับชื่อ "โครงการชลประทาน..." / "โครงการส่งน้ำและบำรุงรักษา..." ของ**กรมชลประทาน (RID)** เช่น "โครงการส่งน้ำและบำรุงรักษารังสิตเหนือ" (6 สถานี), "โครงการชลประทานสงขลา" (15 สถานี), "โครงการชลประทานกำแพงเพชร" (3), "โครงการชลประทานนครนายก" (3) ฯลฯ
- **ไม่พบกลุ่มใดที่เป็นของ BMA/กรุงเทพมหานคร** — ระบบนี้จึงเป็นเครือข่ายโทรมาตรประตูระบายน้ำ**ระดับโครงการชลประทานทั่วประเทศของกรมชลประทาน** ไม่ใช่ระบบประตูระบายน้ำของ กทม. ที่คาดไว้ในตอนแรก
- ตัวแปรที่วัด (setting_node_data_key ที่พบ): `WaterLevel` / `Water_Level` (ระดับน้ำด้านหน้า-ด้านหลัง/ด้านท้าย) · `Flowrate` / `Water_Discharge` (อัตราการไหล) · `Voltage_L1/L2/L3-N` (แรงดันไฟฟ้าของอุปกรณ์เทเลเมทรี — ใช้ตรวจสุขภาพระบบ ไม่ใช่ข้อมูลน้ำ)
- **ไม่มีฟิลด์สถานะ "เปิด/ปิดประตู" (gate open/close) ในเมทาดาต้าที่ดึงได้** — มีเฉพาะระดับน้ำ/อัตราการไหล จุดสีเขียว/แดงในภาพหน้าจอน่าจะหมายถึงสถานะออนไลน์/ออฟไลน์ของอุปกรณ์เทเลเมทรี ไม่ใช่สถานะบานประตู (INSTINCT — ยังไม่ยืนยัน)
- ค่าระดับน้ำที่ปรากฏบนหน้าเว็บเป็น**ค่าจริงที่ไม่ใช่ 0 ทั้งหมด** เช่น "ฝายวังไทร ระดับน้ำด้านหน้า 79.47 ม.รทก.", "ประตูระบายน้ำบางหยี 10 บาน ระดับน้ำด้านท้าย -1.45 ม.รทก." (ณ เวลาที่ดึง 2026-09-27, ~05:57 UTC) — ยืนยันว่าเป็น**ข้อมูล real-time จริง ไม่ใช่ mockup**

## ตำแหน่งสินทรัพย์ (lat/lon) — VERIFIED, สำคัญตามลำดับความสำคัญของ founder
พิกัดฝังอยู่ใน field `floodgate_map` (Google Maps embed iframe) ของแต่ละสถานี ใน 2 รูปแบบซ้อนกัน:
1. `!2d<lon>!3d<lat>` — พิกัดจุดศูนย์กลางแผนที่ (**มักซ้ำกันทั้งกลุ่ม** เช่น 6 สถานีใน "รังสิตเหนือ" ใช้ค่าเดียวกันหมด 14.166260774102282, 100.81078341953125 — ไม่ใช่ตำแหน่งจริงของแต่ละสถานี)
2. `!2z<base64>` — ป้าย DMS เฉพาะจุด เช่น `MTTCsDExJzQ5LjAiTiAxMDDCsDUyJzA0LjgiRQ` ถอดรหัส base64 ได้ `14°11'49.0"N 100°52'04.8"E` — **นี่คือพิกัดจริงเฉพาะสถานี**

**ผลตรวจสอบ**: จาก 67 สถานี มี **57 สถานี (85%)** ที่มีป้าย DMS เฉพาะจุด (`!2z`) ถอดรหัสได้ และ **28 สถานีในจำนวนนั้น (49%)** มีพิกัดต่างจากจุดศูนย์กลางแผนที่ของกลุ่มเกิน 0.001 องศา (~100 ม.) อย่างมีนัยสำคัญ → **ต้องใช้ค่าจากป้าย `!2z` (ถอดรหัส DMS→decimal) ไม่ใช่ `!2d/!3d`** เพื่อความแม่นยำระดับสถานี

- **รูปแบบ**: ฝังใน HTML string ของ iframe (ต้อง regex extract, ไม่ใช่ field lat/lon ตรงๆ)
- **จำนวนแถวที่ใช้ได้**: 57/67 สถานี มีพิกัดแม่นยำระดับสถานี, อีก 10 สถานีมีเฉพาะพิกัดศูนย์กลางกลุ่ม (แม่นยำต่ำ)
- **stable id**: มี — `floodgate_id` เป็นตัวเลขคงที่ต่อสถานี (เช่น 33, 44, 121, 137) ตรงกับ path ของรูปภาพใน minio ด้วย (`floodgate-images/<floodgate_id>/...`)

## สิ่งที่ FloodConnect ใช้ได้ทันที
**ฟีดนี้มีพิกัด + ค่าระดับน้ำ real-time สำหรับ 67 สถานีทั่วประเทศ (ไม่ครอบคลุมกรุงเทพฯ/ปริมณฑลโดยตรงเท่าที่เห็น ยกเว้น "รังสิตเหนือ" ปทุมธานี ซึ่งอยู่ติดกรุงเทพฯ ทางเหนือ)** — ไม่มีใน `sources/registry.yaml` ปัจจุบัน เป็นฟีดใหม่ที่มีพิกัดสถานีชัดเจนที่สุดเท่าที่พบในรอบสำรวจนี้ทั้งหมด (เทียบกับ TMD/GISTDA/ONWR ที่ยังไม่ยืนยันพิกัดเชิงกลไก) — ควรพิจารณาต่อ API `FloodgateInfo` (POST, ไม่ต้อง auth) เป็นฟีดหลักสำหรับ static asset positions ในระบบ WATER_SYSTEM_DAG ระดับโครงการชลประทาน แต่ **ต้องยืนยันเจ้าของ/สิทธิ์การใช้ข้อมูลก่อนนำเข้าระบบจริง** เพราะไม่ใช่โดเมนราชการ
