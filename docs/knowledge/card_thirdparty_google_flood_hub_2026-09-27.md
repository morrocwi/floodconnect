## 2. วิธีการของ Google ตามคำอธิบายสาธารณะที่ทราบกันทั่วไป (RELAYED-general — ยังไม่ fetch primary source รอบนี้)

- โมเดล ML ระดับโลกคาดการณ์ discharge/water level ที่ **gauge จริง** (พื้นที่ที่มีสถานีวัด) และ
  **virtual gauge** (จุดที่ไม่มีสถานีจริง แต่โมเดลประเมินจากภูมิประเทศ+อุทกวิทยาข้างเคียง) — คล้าย
  แนวคิดเดียวกับ GloFAS แต่ Google ฝึกโมเดลของตัวเองบน hydrography ทั่วโลก
- คะแนนความเสี่ยงต่อจุด เทียบกับ **return-period threshold** ของจุดนั้น (เช่น "เกินระดับที่เคยเกิด
  1 ใน 5 ปี" ฯลฯ) ไม่ใช่ค่าดิบ m³/s ตรงๆ — นี่คือความต่างสำคัญจากค่า discharge ดิบที่คลังนี้มีอยู่
- พื้นที่แรเงา (inundation extent) มาจากโมเดล/ภาพดาวเทียมที่ฝึกแยกต่างหากสำหรับประเมินพื้นที่น้ำท่วม
  จริงบนพื้นดิน ไม่ใช่แค่ค่าจากสถานีน้ำ
- ตัวเลข "ประชากร"/"พื้นที่" ที่ได้รับผลกระทบ มาจากการซ้อนทับพื้นที่แรเงากับชั้นข้อมูลประชากร
  (เช่น WorldPop/Google population layer) แบบ offline ไม่ใช่ real-time census

## 3. สิ่งที่ Google มีแต่คลังนี้ยังไม่มี (gap, ซื่อสัตย์)

| รายการ | Google Flood Hub | คลังนี้ (thailand_flood_kg) |
|---|---|---|
| ประชากร/พื้นที่ที่ได้รับผลกระทบต่อเหตุการณ์ | มี (11M คน, 75,000 กม.²) | **ไม่มี** — ไม่มีชั้นข้อมูลประชากรใดๆ ในคลัง (ดู §5 NATIONWIDE_RISK_LAYER_DESIGN.md) |
| พื้นที่น้ำท่วมจริง (inundation shading) | มี (จากโมเดล+ดาวเทียม) | **ไม่มี** — ไม่มีโมเดล inundation ของตัวเอง |
| Return-period risk level ต่อจุด (4 ชั้น) | มี (จุดทุกจุดมีระดับ) | **มีบางส่วน** — เฉพาะจุดที่มีประวัติย้อนหลังยาวพอ (`sources/coping_thresholds.yaml`, HII history ~3 ปี) ไม่ครบทุกจุด |
| Virtual gauge ครอบคลุมทุกลำน้ำ | มี (ผ่านโมเดลของ Google) | **ไม่มี** — คลังนี้มีเฉพาะจุดที่มีสถานีจริง (thaiwater_waterlevel 804 สถานี) หรือจุดที่เลือก sample เอง (openmeteo_flood ปัจจุบันมีแค่ 3 จุด) |
| ระยะเวลาที่คาดว่าจะดำเนินต่อ (duration forecast) | มี ("อย่างน้อย 5 วัน") | **ไม่มี** — `PROP-FLOOD-02` (time-to-threshold) ยังไม่ implement (AGENTS.md §8) |

## 4. Google/สกรีนช็อตนี้กลายเป็น INPUT ของคลังนี้อย่างไร

**ตอนนี้ (ไม่มี API)**: ใช้ **screenshot-as-observation** — บันทึกค่าที่อ่านได้จากภาพ (ตาราง §1) เป็น
แถวเดียวใน `readout_log`/การ์ดความรู้แบบนี้ ทุกครั้งที่มีสกรีนช็อตใหม่ (RELAYED, tag ต้นทาง
`google_flood_hub_screenshot`), ใช้เป็น **cross-check เชิงคุณภาพ** เท่านั้น — เทียบว่าโซนที่เรา
ประเมินเป็น L3+ ตรงกับโซน "อันตราย/อันตรายมาก" ของ Google หรือไม่ (ดู falsifier ใน
`docs/NATIONWIDE_RISK_LAYER_DESIGN.md` §4) — **ห้ามใช้ตัวเลขประชากร/พื้นที่ของ Google เป็นตัวเลข
ของคลังนี้เอง** เพราะไม่รู้ methodology ที่แม่นยำพอจะรวมเข้ากับ tier ของเรา (ยังคง RELAYED เสมอ)

**เมื่อมี API** (`google_flood_hub_api`, ปัจจุบันสถานะ waitlist/pilot-only ตาม
`docs/knowledge/GLOBAL_FREE_HAZARD_APIS.md`): จะกลายเป็นแหล่ง `layer0_in`/`promoter` อีกตัวคู่กับ
GloFAS ผ่าน Open-Meteo — field ที่ต้องการคือ gauge-level return-period risk level (แม็ปเป็น
promoter เพิ่มใน PROP-FLOOD-06 เมื่อ registered ผ่าน Toledo, ไม่ใช่สมการใหม่) — งานนี้ไม่ implement
เพราะ API ยังไม่เปิดให้ทั่วไป (**OPEN**, ต้องรอ pilot access ตามที่บันทึกไว้แล้วในเอกสารเดิม)

## 5. Epistemic summary

- MEASURED: ทุกค่าในตาราง §1 (อ่านจากภาพจริง)
- RELAYED-general: วิธีการของ Google ใน §2 (ไม่ได้ fetch primary source รอบนี้)
- OPEN: ตัวเลข "จุดเขียว" หมายถึงอะไรแน่ (ไม่มีคำอธิบายใน legend ที่ถ่ายอยู่ในภาพ), สถานะ API access
  ปัจจุบัน (อาจเปลี่ยนหลังวันที่การ์ดนี้เขียน)

*ไม่มีสมการในไฟล์นี้ — เป็นการ์ดความรู้เชิงพรรณนาเท่านั้น, ไม่มีชื่อบุคคล, ไม่มี path เครื่อง local*
