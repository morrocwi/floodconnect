  เอง" ไม่ใช่การสำรวจครบทั้งฝั่งตะวันออก) — นี่คือ**ขอบเขตที่ตั้งใจ** ไม่ใช่ความผิดพลาด
- `sources/capacity_ledger.yaml` **มีทางออกที่สอง (สู่อ่าวไทย) อยู่แล้ว**: แถว `outfall:east_seaside_rid`

  `docs/knowledge/DRAINAGE_CAPACITY_MAP.md` §1 มี subgraph `SEASIDE` แยกต่างหากจาก `OUTLET` (เจ้าพระยา)
  อยู่แล้วในผังเดิม

**ส่วนที่เป็นช่องว่างจริง**:
1. **ไม่มี control node เฉพาะของ Nong Chok / Phra Ong Chaiyanuchit / Chonlahan Phichit** ใน
   `water_system_dag.mmd`/`east_chain.yaml`/`capacity_ledger.yaml` เลย — ทางออกที่สองมีอยู่แค่ระดับ
   "aggregate" (`outfall:east_seaside_rid`, ประตู 34 บาน aggregate) ไม่มีโครงสร้างแยกเป็นราย node แบบที่

   `capacity_ledger.yaml` (ยืนยันซ้ำจาก DRAINAGE_CAPACITY_MAP.md §4.3: "ค้นแล้วไม่พบเกณฑ์ตัดสิน (threshold)

   ผู้ควบคุมจริง — ตรงกับที่งานนี้เสนอเพิ่มใน §3 ด้านล่าง — **ยืนยันซ้ำจาก 8-URL fetch รอบสอง**: claim #6

### 6.2 คำตัดสิน — "น้ำบางปะกงไหลเข้าลาดพร้าว" ผิดหรือถูก

**INSTINCT ของงานนี้ (ไม่ใช่การพิสูจน์)**: ข้อความที่ว่า **"น้ำบางปะกงไหลเข้าลาดพร้าว" ผิดในความหมายทิศทาง
ออกแบบ (design direction)** — เหตุผล:

1. URL #6 (plan50, VERIFIED) ระบุตรงว่าโครงการ RID ที่หกวาสายล่าง/แสนแสบ/ประเวศ มีทิศทาง **"เพื่อเร่งผันน้ำ
   จากพื้นที่ลงสู่แม่น้ำบางปะกงและทะเล"** — คือ **ไหลออก** จากหกวาสายล่างไปบางปะกง ไม่ใช่ไหลเข้า
2. ลาดพร้าวเองมีทิศทางออกแบบไหลลงแสนแสบ→พระโขนง/อุโมงค์→เจ้าพระยา (`tunnel:bma_dds:saensaeb_ladprao`,
   `outfall:phra_khanong`) — คือ**ไหลออกไปเจ้าพระยาเช่นกัน** ไม่ใช่รับน้ำจากบางปะกง
3. สิ่งที่ **plausible จริง** ตามคำเตือนของบุคคลที่สามเอง (ไม่ใช่ literal reverse-flow) คือ
   **ปรากฏการณ์ backwater ที่ขึ้นกับระดับน้ำ (stage-dependent)**: เมื่อระดับน้ำบางปะกงสูง (ΔH ที่ทางออก
   ฝั่งบางปะกงลดลง) ความสามารถระบายออกทางแขนคลอง 13/RID จะลดลง → น้ำค้างอยู่ใน Lower Hok Wa มากขึ้น →
   เพิ่มภาระต่อลาดพร้าวตอนบน (ทางอ้อม ไม่ใช่การไหลย้อนโดยตรงของน้ำบางปะกงเอง) — กลไกนี้**สอดคล้องกับ
   PROP-FLOOD-06's D_H/R_H term-selection logic ที่มีอยู่แล้ว** (`docs/knowledge/DRAINAGE_MODE_SOURCES.md`
   §5) แต่**ไม่มีสมการใหม่ในการ์ดนี้** — ทำเครื่องหมายเป็น attribute `backwater_risk: OPEN` บน edge เท่านั้น
   (ดู YAML §3)

**สรุปให้ฟาวน์เดอร์**: ทิศทางออกแบบทั้งสองแขนของ Lower Hok Wa คือ **"ไหลออก" ทั้งคู่** (ไปเจ้าพระยา และไป
บางปะกง/ทะเล) — ไม่ใช่ทางที่น้ำบางปะกงไหลเข้ามา ข้อที่เป็นจริงได้คือ **backwater ลดความสามารถระบายออก
ฝั่งบางปะกง ทำให้ภาระตกกับแขนลาดพร้าวมากขึ้น** ซึ่งยัง **ไม่มีการวัดจริง (OPEN)** ในคลังนี้ — ตรงกับ caveat
ที่บุคคลที่สามเขียนไว้เองแล้ว ("no measured propagation")
