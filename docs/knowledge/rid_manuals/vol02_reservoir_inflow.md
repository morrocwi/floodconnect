## วัตถุประสงค์และขอบเขต (น. 2-1)

- วัตถุประสงค์: มาตรฐานการปฏิบัติงานประเมินปริมาณน้ำไหลลงอ่าง; ถ่ายทอดให้ผู้เข้าใหม่; **ผลใช้วางแผนจัดสรรน้ำ และจัดทำโค้งปฏิบัติการอ่างเก็บน้ำ (เล่ม 9)** (ข้อ 1.3).
- ขอบเขต: ประเมินจาก **ข้อมูลน้ำท่าในภูมิภาค** (รายเดือน) และอาจใช้ข้อมูลฝนประกอบ เพื่อต่อขยายข้อมูลให้ยาวขึ้นด้วยโปรแกรม HEC-4.
- คำจำกัดความ: ปริมาณน้ำไหลลงอ่าง "เปรียบเสมือนต้นทุนที่มีอยู่ของโครงการ" ใช้กำหนดพื้นที่เพาะปลูกได้; ควรมีสถิติยาวนานครอบคลุมช่วงแล้ง/น้ำมากที่อาจติดต่อกันหลายปี (ข้อ 3).
- **ข้อสังเกต (INSTINCT):** เล่มนี้เป็น inflow **รายเดือน/รายปีเชิงสถิติเพื่อวางแผน** ไม่ใช่การพยากรณ์ inflow รายวันช่วงน้ำหลาก — ส่วนน้ำหลากอยู่ในเล่ม 3.

## กระบวนการ (ผังกระบวนการ น. 2-2; ขั้นตอน น. 2-3)

1. **เก็บรวบรวมข้อมูล** (3 วัน; ผอน.ภาค, ผอท.) — น้ำท่ารายเดือนในลุ่มน้ำที่โครงการตั้งอยู่ โดยติดต่อศูนย์อุทกวิทยาและบริหารน้ำภาค หรือกลุ่มงานสารสนเทศและพยากรณ์น้ำ ส่วนอุทกวิทยา.
2. **กรณีมีสถานีน้ำท่าใกล้หัวงานบนลำน้ำเดียวกัน** (2 วัน; ฝจน., ฝสบ.) — แปลงน้ำท่ารายเดือนของสถานีด้วยสัดส่วนพื้นที่รับน้ำฝน (โครงการ/สถานี) → อนุกรมน้ำท่ารายเดือนไหลลงอ่าง (vol02-eq1).
3. **กรณีไม่มีสถานีบนลำน้ำเดียวกัน** (5 วัน) — regression น้ำท่ารายปีเฉลี่ย Q กับพื้นที่ A ของกลุ่มสถานีในลุ่มน้ำย่อย (เพิ่มลุ่มน้ำย่อยข้างเคียงจนได้ความสัมพันธ์ชัด) → Q = kAⁿ (vol02-eq2); แทน A ของโครงการ → น้ำท่ารายปีเฉลี่ย; เลือก **สถานีดัชนี** ใกล้เคียงที่สภาพอุทกวิทยาคล้ายกัน → แฟกเตอร์ปรับค่า (vol02-eq3) → คูณอนุกรมรายเดือนของสถานีดัชนี.
4. **กรณีอนุกรมสั้นเกินไป** (3 วัน) — ต่อขยายด้วย HEC-4 โดยใช้น้ำท่าสถานีใกล้เคียงและฝนประกอบ (ภาคผนวก ค.).

มาตรฐานงาน (น. 2-3): ผลการประเมินมีช่วงสถิติยาวพอ **ประมาณ 30 ปี**.
ระบบติดตาม (น. 2-3): โครงการควรเก็บสถิติ inflow จริงด้วยการคำนวณ **สมดุลน้ำในอ่างรายวัน** จากปริมาตรในอ่าง น้ำส่งให้พื้นที่เพาะปลูก/การใช้อื่น ฝน การระเหย การรั่วซึม (vol02-eq4 — ข้อความ ไม่มีสูตร).
แบบฟอร์ม: "ไม่มีแบบฟอร์มที่ใช้" (น. 2-3).

**vol02-eq1** — ถ่ายโอนน้ำท่าด้วยสัดส่วนพื้นที่ (ข้อความ, น. 2-2 ขั้น 2; น. 2-3 ข้อ 6.2)
$Q_{\text{inflow},m} = Q_{\text{sta},m}\cdot \dfrac{A_{\text{proj}}}{A_{\text{sta}}}$
Q_{·,m} = น้ำท่ารายเดือน m [ล้าน ลบ.ม.]; A = พื้นที่รับน้ำฝน [ตร.กม.]. เงื่อนไข: สถานีอยู่ใกล้หัวงาน **บนลำน้ำเดียวกัน**. (เล่มเขียนเป็นข้อความ "แปลงค่า...ด้วยสัดส่วนของพื้นที่รับน้ำฝน (โครงการ / สถานีข้อมูล)" — รูปสมการเขียนโดยผู้ถอด)
Toledo: not yet looked up — do not use in a derivation until registered (PROP or CANONICAL)

**vol02-eq2** — ความสัมพันธ์น้ำท่ารายปีเฉลี่ยกับพื้นที่ (regression, น. 2-2, 2-3; ตัวอย่าง น. 2-5)
$Q = k\,A^{n}$
Q = น้ำท่ารายปีเฉลี่ย [ล้าน ลบ.ม./ปี]; A = พื้นที่รับน้ำฝน [ตร.กม.]; k, n = สัมประสิทธิ์ regression ต่อกลุ่มสถานีในลุ่มน้ำย่อย. เงื่อนไข: ใช้เมื่อไม่มีสถานีบนลำน้ำเดียวกัน.
ตัวอย่าง คลองประแสร์ (น. 2-5): $Q = 2.7792\,A^{0.7267}$, R² = 0.9945 จาก 4 สถานี (Z.5, Z.11, Z.16, Z.18).
Toledo: not yet looked up — do not use in a derivation until registered (PROP or CANONICAL)

**vol02-eq3** — แฟกเตอร์ปรับค่าจากสถานีดัชนี (น. 2-3 ข้อ 6.4–6.5; ตัวอย่าง น. 2-5)
$F = \bar Q_{\text{proj}} / \bar Q_{\text{index}}$; $\;Q_{\text{inflow},m,y} = F\cdot Q_{\text{index},m,y}$
$\bar Q$ = น้ำท่ารายปีเฉลี่ย [ล้าน ลบ.ม.]. ตัวอย่าง: F = 291.3/530 = 0.55 (สถานีดัชนี Z.11).

**vol02-eq4** — สมดุลน้ำในอ่างรายวันเพื่อย้อนหา inflow จริง (ข้อความเท่านั้น, น. 2-3 ข้อ 8)
เล่มระบุองค์ประกอบ: ปริมาตรน้ำในอ่าง, น้ำที่ส่งให้พื้นที่เพาะปลูก/การใช้น้ำอื่น, ฝนตก, อัตราการระเหย, การรั่วซึม — **ไม่ได้ให้สูตรหรือเครื่องหมาย** และไม่ได้กล่าวถึงน้ำล้นทางระบายน้ำล้น. ไม่ถอดสูตรจากความจำ.

**vol02-eq5** — การต่อขยายด้วย HEC-4 (น. 2-12)
ข้อความ: แปลงข้อมูลรายเดือนด้วย log ฐาน 10, ประมาณการแจกแจง Pearson Type III, คำนวณ correlation ระหว่างคู่สถานีสำหรับเดือนปัจจุบันและเดือนก่อนหน้า, เติมค่าที่ขาดด้วยสมการ regression เชิงซ้อน (เลือกสัมประสิทธิ์จาก correlation matrix, แก้ด้วย Crout method) พร้อม **random component** จากส่วน nondetermination — **ไม่มีสูตรในเล่ม**.

## ข้อมูลที่ต้องใช้

น้ำท่ารายเดือนของสถานีในลุ่มน้ำ (ส่วนอุทกวิทยา/ศูนย์ภาค), พื้นที่รับน้ำฝนของสถานีและหัวงาน, ฝน (สำหรับ HEC-4), ช่วงข้อมูลรวม ~30 ปี; สำหรับติดตามผล: บันทึกรายวันของปริมาตรอ่าง น้ำส่ง ฝน การระเหย การรั่วซึม.

## ข้อมูลเผยแพร่ vs ภายใน (ตามที่เล่มสื่อ)

- เล่มบอกให้ "ติดต่อ" ศูนย์ภาค/กลุ่มงานสารสนเทศและพยากรณ์น้ำ เพื่อขอน้ำท่ารายเดือน — **ไม่ได้ระบุช่องทางเผยแพร่สาธารณะ** (INSTINCT: ข้อมูลอนุกรมและผลประเมินเป็นเอกสารภายในงานวางแผน).
- โปรแกรม FORTRAN ทั้งชุดเป็นเครื่องมือภายในกรม ไม่ได้ระบุแหล่งดาวน์โหลด.

## ข้อจำกัดที่เล่มระบุ/ที่พบ

- HEC-4: กลุ่มข้อมูลจำกัด 4 สถานี, แต่ละสถานีควรมี > 3 ปี; ค่าที่เติมอาจ "สูงมากผิดปกติ" จาก random component — อาจแทนด้วยค่าเฉลี่ยเดือนนั้น; เอาต์พุตเป็นจำนวนเต็ม ค่า < 0.5 กลายเป็น 0 → ลุ่มเล็กต้องคูณ 100 ก่อน (น. 2-12).
- ความละเอียด **รายเดือน** — ไม่ตอบคำถามน้ำหลากรายวัน/รายชั่วโมง.
- สมดุลน้ำรายวัน (ข้อ 8) เป็นเพียงข้อความแนะนำ ไม่มีสูตร/แบบฟอร์ม.
- ไม่มีผู้อนุมัติที่ระบุชื่อตำแหน่ง.

## สิ่งที่ FloodConnect จะใช้ได้ (INSTINCT, ≤5)

- inflow รายเดือนเฉลี่ยแบบนี้บอก "ฤดูน้ำเข้าอ่าง" (ตัวอย่าง: ก.ย.–ต.ค. สูงสุด) — ใช้เป็นกรอบอธิบายชุมชนว่าช่วงไหนอ่างต้นน้ำมีแนวโน้มต้องระบาย แต่ไม่ใช่สัญญาณรายวัน.
- ถ้าชุมชนอยู่ท้ายอ่าง ให้ขอ (ไม่ใช่คำนวณเอง) อนุกรม inflow/สมดุลน้ำรายวันจากโครงการชลประทานในพื้นที่ — เล่มบอกว่าโครงการ "ควรเก็บ" อยู่แล้ว (ข้อ 8).
- Q = kAⁿ ช่วยตอบคำถามเชิงลำดับขนาดได้ว่าลุ่มย่อยที่ไม่มีสถานีวัดน่าจะให้น้ำปริมาณราวไหน — ต้องผ่าน Toledo ก่อนใช้จริง.
- สำหรับกรุงเทพฯ ฝั่งตะวันออก เล่มนี้ใช้ตรงไม่ได้ (ไม่มีอ่างเก็บน้ำ; ระบบคลอง–สูบ).
