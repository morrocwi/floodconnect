## วัตถุประสงค์และขอบเขต (น. ๔-๑)

- ให้กรมชลประทานมีคู่มือบริหารจัดการน้ำที่ชัดเจน เป็นแนวทางให้ผู้ปฏิบัติงานด้านการจัดสรรน้ำ
- เป็นเครื่องมือช่วยวางแผนการจัดสรรน้ำในอ่างเก็บน้ำ โดยจำลองความต้องการใช้น้ำและปริมาณน้ำไหลเข้าอ่างใน
  ช่วงเวลาต่างๆ เพื่อติดตามสถานการณ์น้ำในอ่าง หลีกเลี่ยงปัญหาขาดแคลนน้ำและน้ำล้นอ่างให้ได้มากที่สุด
- **หากเกิดปัญหาขาดแคลนน้ำหรือน้ำล้นอ่าง จะสามารถคาดการณ์ได้ว่าจะเกิดขึ้นประมาณวันที่เท่าไหร่** เพื่อเตรียม
  มาตรการรองรับสถานการณ์ได้อย่างทันท่วงที — ครอบคลุมการบริหารจัดการน้ำตลอดทั้งปี

## คำจำกัดความ (น. ๔-๑)

การจำลอง (Simulation) = การจำลองของสิ่งที่มีอยู่จริง เหตุการณ์ในอดีต หรือเพื่อคาดการณ์สิ่งที่จะเกิดขึ้นใน
อนาคต หรือขั้นตอนเชิงวิทยาศาสตร์เพื่อชี้ชัดลักษณะอย่างใดอย่างหนึ่งออกมาให้ชัดเจน

## หน้าที่ความรับผิดชอบ (น. ๔-๑)

| ตำแหน่ง | บทบาท |
|---|---|
| หัวหน้าฝ่ายบริหารและจัดการน้ำ (ฝจน.ชป.) | วางแผน+รายงานผลความก้าวหน้าการบริหารจัดการน้ำฤดูฝน/แล้งของโครงการในสังกัดสำนักชลประทาน |
| หัวหน้าฝ่ายจัดสรรน้ำและปรับปรุงระบบชลประทาน (ฝจน.คป./ฝจน.คบ.) | วางแผน+จัดทำรายงานผลของโครงการชลประทาน/โครงการส่งน้ำ |

## เครื่องมือ — โปรแกรม Reservoir Operation Simulation

- เขียนด้วย **Visual Basic for Applications** บน Microsoft Office Excel — รันได้ทุกเวอร์ชัน Windows
- ใช้หลัก **สมดุลน้ำ (water balance)** ของอ่างเก็บน้ำ (inflow, storage, outflow, evaporation, rule curve)
- โครงสร้างชีตกรอกข้อมูล 6 ชีต: Simulation Condition, Simulation (ระดับน้ำ/ปริมาณน้ำในอ่าง/Inflow/ระบาย
  ท้ายเขื่อน), Sheet for chart (URC/LRC, Average, SD, Avg±SD), Monthly Inflow, EL_Area_Vol (โค้งความจุ),
  Evap (อัตราการระเหย)
- ชีตแสดงผล 6 ชีต: Chart ปริมาณน้ำจำลอง+Rule Curve, Chart Daily Inflow/Outflow/Storage, Monthly
  Outflow/Storage
- ใช้งาน 3 กรณี: รันโปรแกรมครั้งแรก, อัพเดทรายสัปดาห์, ขึ้นปีใหม่

## ผังกระบวนการ (น. ๔-๒) — วนรอบทุกสัปดาห์ตลอดฤดู

1. เริ่มกระบวนการข้อมูลพื้นฐาน (สัปดาห์แรกของฤดูแล้ง/ฝน) — รวบรวมข้อมูลพื้นฐานตามคู่มือเล่ม 1/16 —
   ผู้รับผิดชอบ: ฝจน.คป./ฝจน.คบ.
2. จำลองการปฏิบัติการอ่างเก็บน้ำ (ทุกสัปดาห์) — อัพเดทข้อมูลน้ำรายวันถึงปัจจุบัน, ปรับแผนการระบายน้ำจากอ่าง
   (ถ้ามี), ประเมิน/วิเคราะห์ปริมาณน้ำในอ่าง — ผู้รับผิดชอบ: ฝจน.คป./ฝจน.คบ.
3. ติดตามตรวจสอบและปรับแผน (ทุกสัปดาห์) — เก็บข้อมูล/ติดตาม/ตรวจสอบ/ตรวจวัดผล, ปรับแผนการจัดสรรน้ำ
   ให้สอดคล้องกับปริมาณน้ำที่เหลืออยู่ — ผู้รับผิดชอบ: ฝจน.คป./ฝจน.คบ.
4. บริหารจัดการตามแผน (ทุกสัปดาห์) — ดำเนินการตามแผนการจัดสรรน้ำและการเพาะปลูกพืช
5. สิ้นสุดฤดูแล้ง/ฝน (สัปดาห์สุดท้าย) — คาดการณ์ปริมาณน้ำต้นฤดูถัดไป

## ตัวอย่างข้อมูล (น. ๔-๔, ๔-๕) — โครงสร้างข้อมูลที่โปรแกรมต้องการ (อ่างป่าสักชลสิทธิ์)

รายละเอียดอ่าง (ระดับเก็บกัก 42.0 ม., ระดับสันเขื่อน 46.5 ม., ความจุที่ระดับเก็บกัก 785 ล้าน ลบ.ม., Spillway
Crest Length 102.5 ม., Dead Storage 3.0 ล้าน ลบ.ม.), ผลการส่งน้ำจริงรายเดือน, แผนการส่งน้ำรายเดือน,
อัตราการระเหยสะสมรายเดือน, ตารางโค้งความจุ (ระดับ/พื้นที่ผิวน้ำ/ความจุ) — ทั้งหมดเป็นข้อมูลที่ RID เก็บอยู่แล้ว
ต่อเนื่องรายวัน/รายสัปดาห์ในโปรแกรมนี้ แต่ไม่พบช่องทางเผยแพร่สาธารณะในส่วนที่อ่าน

## ความเกี่ยวข้องกับ DAG (`docs/knowledge/WATER_SYSTEM_DAG.md`)

- `AS_DAM_RID` (เขื่อนเจ้าพระยา/ป่าสักชลสิทธิ์), `DT_DAM` (น้ำในอ่าง/แผนระบายเขื่อน), `DC_DAM_RELEASE`
  (ปล่อยน้ำเขื่อน — ผู้ชี้ขาดปริมาณ OPEN ตาม DAG) — เล่มนี้คือ SOP รายสัปดาห์ที่ป้อนข้อมูลเข้าสู่การตัดสินใจ
  `DC_DAM_RELEASE` จริง แต่ยืนยันว่าเป็นกระบวนการวางแผนระดับ **สัปดาห์** ไม่ใช่ real-time ชั่วโมงต่อชั่วโมง
  ที่ FloodConnect ต้องการช่วงน้ำท่วมเฉียบพลัน
- `AG_RID`, `AG_PROV_RID` — ผู้ปฏิบัติ (ฝจน.คป./ฝจน.คบ.) อยู่ระดับโครงการชลประทาน ไม่ใช่ระดับ กทม.

## สิ่งที่ FloodConnect จะใช้ได้ (INSTINCT)

- คำว่า **"หากเกิดปัญหาขาดแคลนน้ำหรือน้ำล้นอ่าง จะสามารถคาดการณ์ได้ว่าจะเกิดขึ้นประมาณวันที่เท่าไหร่"**
  (น. ๔-๑) แสดงว่า RID มีศักยภาพเชิงทฤษฎีในการพยากรณ์ล่วงหน้าระดับสัปดาห์สำหรับอ่างต้นน้ำ — แต่นี่คือ
  น้ำล้น**อ่าง**เก็บน้ำ ไม่ใช่น้ำท่วม**เมือง** ปลายน้ำ (คนละ time scale/spatial scale กับ FloodConnect)
- ยืนยันว่า HEC-3/Excel VBA เป็นเครื่องมือหลักของ RID สำหรับอ่างขนาดใหญ่/กลาง — ถ้าจะขอ feed real-time
  ต้องถามหา output ของโปรแกรมนี้ ไม่ใช่ตัวโปรแกรมเอง
