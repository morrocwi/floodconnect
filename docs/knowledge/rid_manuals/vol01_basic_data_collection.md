## วัตถุประสงค์และขอบเขต (น. ๑-๑)

- ให้กรมชลประทานมีคู่มือเก็บรวบรวมข้อมูลพื้นฐานด้านการจัดสรรน้ำที่ชัดเจน เป็นลายลักษณ์อักษร ใช้ถ่ายทอด
  ให้ผู้เข้าใหม่ และประเมินผลการปฏิบัติงานบุคลากร
- ครอบคลุมการเก็บรวบรวมข้อมูลพื้นฐานของ **โครงการชลประทานทุกขนาด** (ใหญ่/กลาง/เล็ก) — ปริมาณน้ำ
  จัดสรรให้สอดคล้องกับสภาพน้ำต้นทุนของอ่างเก็บน้ำที่มีอยู่ ส่งน้ำให้พื้นที่ในเขตชลประทานของโครงการส่งน้ำและ
  บำรุงรักษา หรือพื้นที่ชลประทานของอ่างเก็บน้ำขนาดกลาง/เล็ก
- ตัวชี้วัดหลักของโครงการ: จำนวนพื้นที่บริหารจัดการน้ำในเขตชลประทาน (ไร่), พื้นที่ชลประทานที่มีการตั้งกลุ่ม
  ผู้ใช้น้ำ (ร้อยละ)

## คำจำกัดความ (น. ๑-๑)

กระบวนการเก็บรวบรวมข้อมูลพื้นฐานด้านการจัดสรรน้ำของโครงการชลประทาน = กระบวนการที่แสดงลำดับขั้นตอน
ในการเก็บรวบรวมข้อมูลเพื่อนำน้ำมาใช้ในกิจกรรมต่างๆ ให้เกิดประโยชน์สูงสุดและยั่งยืนในช่วงฤดูฝนและฤดูแล้งของ
แต่ละปี โดยความร่วมมือของกรมชลประทานและหน่วยงานที่เกี่ยวข้อง รวมถึงเกษตรกร/ผู้ใช้น้ำชลประทานทุก
ภาคส่วนให้เข้ามามีส่วนร่วมในการบริหารจัดการน้ำ

## หน้าที่ความรับผิดชอบ (น. ๑-๒) — ห่วงโซ่การตัดสินใจ 8 ชั้น

| ตำแหน่ง | บทบาท |
|---|---|
| ผู้อำนวยการส่วนบริหารจัดการน้ำ (ผจน.) | วางแผน+ติดตามผลความก้าวหน้าของสำนักชลประทานที่ 1-17 |
| ผู้อำนวยการส่วนจัดสรรน้ำและบำรุงรักษา สำนักชลประทานที่ 1-17 (ผบร.ชป.) | วางแผน+ติดตามผลของโครงการในสังกัด |
| ผู้อำนวยการโครงการชลประทาน/โครงการส่งน้ำและบำรุงรักษา (ผอ.คป./ผอ.คบ.) | วางแผน+ติดตามผลของโครงการชลประทาน |
| หัวหน้ากลุ่มงานจัดสรรน้ำ ส่วนบริหารจัดการน้ำ (กจ.จน.) | วางแผน+รายงานผลของสำนักชลประทานที่ 1-17 |
| หัวหน้าศูนย์ปฏิบัติการจัดสรรน้ำ ส่วนบริหารจัดการน้ำ (ศป.จน.) | วางแผน+รายงานผลของสำนักชลประทานที่ 1-17 |
| หัวหน้าฝ่ายบริหารและจัดการน้ำ (ฝจน.ชป.) | วางแผน+รายงานผลของโครงการในสังกัดสำนักชลประทาน |
| หัวหน้าฝ่ายจัดสรรน้ำและปรับปรุงระบบชลประทาน (ฝจน.คป./ฝจน.คบ.) | วางแผน+จัดทำรายงานผลของโครงการชลประทาน/โครงการส่งน้ำ |
| หัวหน้าฝ่ายส่งน้ำและบำรุงรักษา (ฝสบ.คป/ฝสบ.คบ.) | วางแผน+จัดทำรายงานผลของโครงการชลประทาน/โครงการส่งน้ำ (ผู้เก็บสถิติจริง ตามผังกระบวนการ) |

**ข้อสังเกต (INSTINCT)**: เป็นสายบังคับบัญชาชั้นเดียวภายใน RID เช่นเดียวกับเล่ม 9 (rule curve) — 8 ชั้น ไม่ใช่
หลายหน่วยงานข้ามสังกัด แต่ยืนยันภาพว่าแม้การ "เก็บข้อมูล" ระดับปฏิบัติการก็ยังไหลผ่านหลายชั้นก่อนถึงผู้ใช้จริง

## ผังกระบวนการ (น. ๑-๓, ๑-๔) — วนซ้ำทุกวัน/ทุกสัปดาห์

1. เริ่มจัดเก็บข้อมูล (ทุกวัน/ทุกสัปดาห์) — ข้อมูลรวมทั้งประเทศ (อ้างอิงพจนานุกรมข้อมูลโครงการพัฒนาระบบ
   สารสนเทศแหล่งน้ำและระบบชลประทาน) + ข้อมูลแยกรายสำนักชลประทานที่ 1-17 — ผู้รับผิดชอบ: ฝสบ.คป./ฝสบ.คบ.
2. ตรวจสอบความถูกต้องของข้อมูล — เทียบกับโครงการฯ หากคลาดเคลื่อนให้ตรวจสอบใหม่ — ผู้รับผิดชอบ: ผอ.คป./
   ผอ.คบ./ฝจน.คป./ฝจน.คบ.
3. จัดเก็บและแสดงผลข้อมูล (ทุกสัปดาห์) — เข้าระบบฐานข้อมูลเพื่อเรียกใช้ต่อ — ผู้รับผิดชอบ: ผบร.ชป./ฝจน.ชป.
4. สิ้นสุดกระบวนการ (จบฤดูฝน/ฤดูแล้ง) — นำข้อมูลไปประเมิน/วิเคราะห์ปริมาณน้ำต้นทุนและความต้องการใช้น้ำ
   ในภาคต่างๆ ของอ่างเก็บน้ำขนาดใหญ่/กลาง — ผู้รับผิดชอบ: ผจน./กจ.จน./ศป.จน.

เผยแพร่หรือ interoperate กับภายนอกเป็นฟีดสาธารณะ

## ข้อมูลที่ RID เก็บอยู่แล้วแต่ไม่ใช่ฟีดสาธารณะ (INSTINCT)

- ข้อมูลรวมทั้งประเทศ + แยกรายสำนักชลประทานที่ 1-17 ของ "พื้นที่บริหารจัดการน้ำในเขตชลประทาน" และ
  "พื้นที่ชลประทานที่มีการตั้งกลุ่มผู้ใช้น้ำ" — ปรับปรุงทุกวัน/ทุกสัปดาห์ในระบบฐานข้อมูลภายใน แต่การ์ดนี้ไม่พบ
  ช่องทางเผยแพร่สาธารณะแบบ real-time ในส่วนที่อ่าน (OPEN ว่ามีหรือไม่ในหน้าที่ยังไม่ได้อ่าน)

## ความเกี่ยวข้องกับ DAG (`docs/knowledge/WATER_SYSTEM_DAG.md`)

- `AG_RID`, `AG_PROV_RID` (โครงการชลประทานจังหวัด/สำนักชลประทานที่ N) — เล่มนี้คือ SOP ต้นทางของการ
  เก็บข้อมูลที่ป้อนเข้า `DT_RID_TELE` และ `DT_DAM` ทางอ้อม (ข้อมูลพื้นฐานโครงการ ไม่ใช่โทรมาตรวัดจริง)
- ไม่พบเส้นเชื่อมตรงไปยังโหนดน้ำท่วมกรุงเทพฯ (`CH_*`, `PP_*`) ในส่วนที่อ่าน — เล่มนี้เป็นข้อมูลระดับแผนจัดสรร
  น้ำเกษตร ไม่ใช่ real-time สถานะประตูน้ำ

## สิ่งที่ FloodConnect จะใช้ได้ (INSTINCT)

- ยืนยันว่า RID มี "ฐานข้อมูลมาตรฐาน" ภายในระดับโครงการอยู่แล้ว (ชื่อฟิลด์/แบบฟอร์มเฉพาะ) — ถ้าจะขอข้อมูล
  จาก RID ควรอ้างอิงรหัสแบบฟอร์มเหล่านี้แทนการขอข้อมูลแบบเปิดกว้าง
- ไม่มีเนื้อหาที่ใช้ตรงกับสถานการณ์น้ำท่วมเฉียบพลันของสัมมากร — เป็นข้อมูลพื้นฐานเกษตร/จัดสรรน้ำรายปีเป็นหลัก
