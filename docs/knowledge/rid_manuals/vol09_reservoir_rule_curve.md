## วัตถุประสงค์และขอบเขต (น. ๙-๑)

- จัดทำมาตรฐานการทำงานที่ชัดเจนสำหรับกิจกรรม/กระบวนการของส่วนบริหารจัดการน้ำ, ใช้ถ่ายทอดให้ผู้เข้าใหม่,
  ใช้ประเมินผลการปฏิบัติงานบุคลากร
- ขอบเขต: ครอบคลุมโครงการชลประทานที่มีอ่างเก็บน้ำขนาดใหญ่/กลางทั้งประเทศ — หาความต้องการใช้น้ำของ
  กิจกรรมต่างๆ (ชลประทาน, อุปโภคบริโภค, อุตสาหกรรม, รักษาระบบนิเวศ) ปริมาณน้ำไหลเข้าอ่าง และข้อกำหนด
  การระบายน้ำ เพื่อจัดทำโค้งปฏิบัติการอ่างเก็บน้ำ

## คำจำกัดความหลัก (น. ๙-๒)

- **ระดับเก็บกักต่ำสุด (Minimum Pool Level)** — ปากอาคารทางออก; ต่ำกว่านี้ = ปริมาตรสูญเปล่า (Dead Storage)
- **ระดับเก็บกักปกติ (Normal Pool Level)** — ระดับเก็บกักสูงสุดของการปฏิบัติงานปกติ; ปริมาตรระหว่างต่ำสุด–ปกติ
  = ปริมาตรใช้การ (Active Storage)
- **ระดับเก็บกักสูงสุด (Maximum Water Surface)** — ปริมาตรส่วนเกิน (Surcharge Storage) กันน้ำท่วมไม่ให้ไหล
  เร็ว/แรงเกินไปท้ายน้ำ
- **ระดับควบคุมตอนบน (Upper Rule Curve, URC)** — เพดานที่ห้ามเกินในแต่ละเดือน เพื่อสำรองที่ว่างรับน้ำหลาก
  ป้องกันน้ำท่วม
- **ระดับควบคุมตอนล่าง (Lower Rule Curve, LRC)** — พื้นที่ต่ำสุดที่ห้ามลดต่ำกว่าในแต่ละเดือน เพื่อสำรองน้ำแล้ง

## หน้าที่ความรับผิดชอบ (น. ๙-๒–๙-๓) — ห่วงโซ่การตัดสินใจ 6 ชั้น

แต่ละชั้นมีวลี **"ตัดสินใจสั่งการอย่างใดอย่างหนึ่ง"** ซ้ำกันในทุกระดับ (ไม่ใช่วลีเดียวที่ผูกกับตำแหน่งเดียว):

| ตำแหน่ง | บทบาท |
|---|---|
| ผู้อำนวยการสำนักบริหารจัดการน้ำและอุทกวิทยา (ผส.บอ.) | รับทราบ ควบคุม ติดตามเกณฑ์เก็บกักน้ำของสำนักชลประทานที่ ๑–๑๗ ตลอดจนตัดสินใจสั่งการ |
| ผู้อำนวยการส่วนบริหารจัดการน้ำ (ผจน.) | รับทราบ ตรวจสอบ ติดตาม พร้อมเสนอแนะทางเลือก |
| ผู้อำนวยการสำนักชลประทานที่ ๑–๑๗ (ผส.ชป.๑-๑๗) | รับทราบ ควบคุม ติดตามเกณฑ์ของโครงการในสังกัด |
| ผู้อำนวยการส่วนจัดสรรน้ำและบำรุงรักษา สำนักชลประทานที่ ๑–๑๗ (ผบร.ชป.๑-๑๗) | วางแผน ควบคุม ติดตาม |
| ผู้อำนวยการโครงการชลประทาน (ผอ.คป.) / ผู้อำนวยการโครงการส่งน้ำและบำรุงรักษา (ผอ.คบ.) | วางแผน ควบคุม ติดตามเกณฑ์ของโครงการที่ตนรับผิดชอบ ตลอดจนตัดสินใจสั่งการ |
| หัวหน้าฝ่ายจัดสรรน้ำและปรับปรุงระบบชลประทาน / หัวหน้าฝ่ายส่งน้ำและบำรุงรักษา (ฝจน./ฝสบ.) | นำเสนอ จัดทำ วิเคราะห์ ประเมิน รายงาน / เก็บรวบรวมข้อมูล ประสานงาน |

**ข้อสังเกต (INSTINCT)**: นี่คือสายบังคับบัญชาชั้นเดียว (RID ภายในองค์กร ไม่ใช่หลายหน่วยงานข้ามสังกัด) —
6 ชั้นแต่ละชั้น "ตัดสินใจสั่งการ" ได้ในขอบเขตของตน ไม่ใช่ผู้บังคับบัญชาหลายคนแย่งอำนาจเดียวกัน — ต่างจาก
รูปแบบความขัดแย้งใน C1 (ผู้สั่งการต่างหน่วยงานขัดกันในโหนดเดียว) แต่ยืนยันว่าแม้ภายในหน่วยงานเดียว
ก็ยังมีจุดตัดสินใจหลายชั้น ซึ่งเพิ่มความหน่วง (latency) ในการปรับเกณฑ์

## ผังกระบวนการ (น. ๙-๔) — 4 ขั้นตอน รวม ~19 วัน

1. รวบรวมข้อมูลพื้นฐาน (7 วัน) — ข้อมูลอ่างเก็บน้ำ, อุตุ-อุทกวิทยา, ความต้องการใช้น้ำ, ข้อมูลอื่นๆ
   (ผู้รับผิดชอบ: ฝสบ.คบ./ฝสบ.คป., ฝจน.คบ./ฝจน.คป.)
2. คำนวณและจัดทำ Reservoir Operation Rule Curves (3 วัน) — ใช้เทคนิคทำสมดุลน้ำ + โปรแกรม HEC-3
   (ป้อนข้อมูลผ่าน Excel), คำนวณฝนใช้การด้วยโปรแกรมย่อยจาก WUSMO, ใช้ข้อมูลย้อนหลังอย่างน้อย 20 ปี
3. ตรวจสอบ ปรับปรุง และแก้ไข (2 วัน) — เทียบผลลัพธ์กับเกณฑ์ที่กำหนด, วนซ้ำจนผ่าน
4. สรุปผลการ (7 วัน) — ประชุม/นำเสนอ/ขอความเห็นชอบ → นำไปวางแผนจัดสรรน้ำในอ่าง → กำหนดรูปแบบส่งน้ำ
   ในเขตโครงการ และเสนอ สชป./กรมฯ

## เครื่องมือ (น. ๙-๕)

- โปรแกรม **HEC-3** (สมดุลน้ำ/จำลองอ่างเก็บน้ำ), โปรแกรมย่อยจาก **WUSMO** (ฝนใช้การ), Excel (ป้อนข้อมูล)
- ข้อมูลย้อนหลังอย่างน้อย 20 ปีนับจากปัจจุบัน

## ข้อเสนอแนะท้ายเล่ม (น. ๙-๒๐) — ความสำคัญต่อ FloodConnect (INSTINCT)

- **Rule curve เป็นเพียงแนวทางช่วยตัดสินใจ ไม่ใช่คำสั่งอัตโนมัติ** — "เกณฑ์การบริหารจัดการน้ำตามผลการศึกษา
  เป็นเพียงแนวทางช่วยตัดสินใจในการควบคุมน้ำในอ่างเก็บน้ำ... ไม่ว่าอย่างไรก็ดีในการบริหารจัดการน้ำระหว่าง
  ฤดูกาลจำเป็นที่โครงการฯ จะต้องมีการติดตามสถานการณ์และแนวโน้มต่างๆ ควบคู่ไปด้วย" — คนตัดสินใจจริง
  (ผอ.คป./ผอ.คบ. ตามห่วงโซ่ข้างต้น) ยังมีอำนาจเบี่ยงเบนจากเกณฑ์ตามสถานการณ์จริง
- เมื่อระดับน้ำสูงกว่า URC ให้พยายามปล่อยน้ำลดระดับลงมาที่ URC โดยไม่เกินปริมาณที่ก่อให้เกิดอุทกภัยท้ายน้ำ
  (Overtop prevention เมื่อสูงกว่าระดับเก็บกักปกติ)
- ควรปรับปรุงเกณฑ์เป็นระยะให้ทันสมัยตามสภาพน้ำต้นทุน/ฝน-น้ำท่า/การใช้น้ำที่เปลี่ยนไป

## ความเกี่ยวข้องกับ 7 ข้อสรุปของ orchestrator

- **C1** (ไม่มีหน่วยงานเดียวรับผิดชอบ): เล่มนี้แสดงว่า **ภายใน RID เอง** มีห่วงโซ่การตัดสินใจ 6 ชั้นสำหรับ
  การปรับเกณฑ์อ่างเดียว — เพิ่มความหน่วง แต่ไม่ใช่ตัวอย่างของ "ผู้สั่งการต่างหน่วยงานขัดกัน" ตรงๆ (เป็นสาย
  บังคับบัญชาเดียว) — ไม่ยืนยันหรือหักล้าง C1 โดยตรง แต่เพิ่มมิติ "หน่วงภายในองค์กรเดียว" ให้คำถามเรื่อง
  governance latency
- **C3** (ข้อมูลมีแต่การตัดสินใจไม่ไหลออก): rule curve คือเอกสารวางแผนภายในหน่วยงาน ไม่พบว่าเผยแพร่ต่อ
  สาธารณะที่ใดในส่วนที่อ่าน — สอดคล้องกับทิศทางของ C3 แต่เป็นข้อมูลระดับแผน ไม่ใช่ระดับ real-time gate state
