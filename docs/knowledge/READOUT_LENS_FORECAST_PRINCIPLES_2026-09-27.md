# หลักการพยากรณ์ของโลก อ่านผ่านเลนส์ readout → แปลเป็นเลนส์สารสนเทศไม่ต่อเนื่อง (IDM) — 2026-09-27

**คำสั่งฟาวน์เดอร์ (คำต่อคำ)**: "เอาสมการพยากรณ์โลก หลักการน้ำ หลักการความกดอากาศต่างๆ มาอ่านผ่านเลนส์ readout
แล้วมองด้วยจักรวาลทีละเก้าสารสนเทศ แล้วแปลงเป็นเลนส์เรา แล้วสร้างสมการพยากรณ์ของเราเองที่[ยืน]บนพื้นที่ Toledo
แล้วลองพยากรณ์แต่ละระดับดูว่าตรงแค่ไหน ด้วยข้อมูลน้อยที่สุด"

**ขอบเขตรอบนี้ (ฟาวน์เดอร์ตัดสิน, คำต่อคำ)**: "เพื่อไม่ให้ขยาย เอาแค่ที่ กทม ก่อน แล้วอันอื่นค่อยๆ ขยับไปเทส" —
**ทดสอบเฉพาะ กทม. รอบนี้ — พื้นที่อื่นขยายทีหลัง** (ดู `docs/MVP_SCOPE_2026-09-27.md`). หลักการในไฟล์นี้เขียนแบบ
ทั่วไป (ใช้กับ lat/lon ใดก็ได้ในอนาคต) แต่ไม่มีการอ้างผลนอก กทม.

**ไฟล์นี้ครอบ step 1–2** (อ่านหลักการโลก → แปลเป็นเลนส์ IDM). Step 3–4 (Toledo pipeline + ชุดสมการรายระดับ) อยู่ใน
Toledo worktree `docs/proposals/PROP-FLOOD-10-ZOOM-FORECAST-DRAFT.md` + `registry/proposals/flood_zoom_forecast.DRAFT.json`;
step 5 (ทดสอบข้อมูลจริง) อยู่ใน `docs/experiments/2026-09-27-zoom-forecast-real-backtest.md`.

**สถานะไฟล์**: การ์ดความรู้ (เขียนไฟล์ใหม่เท่านั้น ไม่แก้ไฟล์อื่น ไม่ commit). **ไม่มีสมการใดในไฟล์นี้ถูกใช้ในโค้ด/หน้าเว็บ**
— สมการโลกทุกตัวด้านล่างถูก "อ่าน" เพื่อดูว่ามันอ่านอะไรออกมาจริง ไม่ได้ถูกนำมาใช้; ตัวที่เรานำไปใช้ต่อผ่าน Toledo
pipeline เท่านั้น และสถานะอยู่ในคอลัมน์ "Toledo" ของแต่ละแถว.

Tag: `VERIFIED` ตรวจเองในงานนี้ · `MEASURED` ผลที่รัน/อ่านจากคลังนี้เอง · `RELAYED` ความรู้ตำรา/แหล่งอื่นที่ไม่ได้ตรวจเอง

## 0. คำถามเปิดที่ต้องให้ฟาวน์เดอร์ยืนยันก่อน (OPEN)

1. **การตีความ "สมการพยากรณ์ของเราเอง"** — ไฟล์นี้ตีความว่า: สมการที่ *เรา derive เองผ่านเลนส์ readout/IDM*
   แทนการลอกโมเดลภายนอก (NWP, Manning, Saint-Venant ฯลฯ) มาใช้ตรงๆ — **แต่ยังต้องผ่านท่อ Toledo** (reuse parent
   ที่ขึ้นทะเบียนแล้ว → derive เฉพาะส่วนที่ขาด → ติดป้าย NEW DERIVATION / PROPOSAL — not yet in Toledo). ไม่มีสมการใด
   ใช้นอกท่อนี้ (กฎถาวร). **ถ้าฟาวน์เดอร์หมายถึงอย่างอื่น** (เช่น "สร้างโมเดลตัวเลขพยากรณ์อากาศของเราเอง" = รัน
   stepper บรรยากาศเอง) — นั่นเป็นงานคนละขนาด และข้อมูลในคลังนี้ไม่พอ (ไม่มีสนามความกด/ลม/ความชื้นเก็บไว้เลย) → OPEN.
2. **"จักรวาลทีละเก้าสารสนเทศ"** — ไฟล์นี้อ่านว่า "มองจักรวาลทีละก้าวของสารสนเทศ" = ก้าว (tick) จำกัด, เซลล์จำกัด,
   ค่าที่อ่านได้มีความละเอียด ε (ตรงกับ IDM + Genesis II.1 stepper). ถ้าคำว่า "เก้า" หมายถึงโครงสร้าง 9 ส่วน/9 ชั้น
   เฉพาะ ที่ฟาวน์เดอร์มีในใจ — ยังไม่พบในคลัง/Toledo ที่อ่าน → OPEN (INSTINCT: น่าจะเป็นคำพิมพ์ของ "ก้าว").

## 1. Lens note (main.hub Step 0 — ก่อนจัดประเภทปัญหา)

- สิ่งที่คงอยู่จริง (retained difference) ในคลังนี้: (ก) ค่าพยากรณ์ฝนจำกัดต่อวัน/ชม. ต่อจุดกริดต่อโมเดล ที่ออก ณ
  เวลาที่รู้, (ข) ค่ามาตรวัดฝน 24 ชม./ระดับคลอง ราย tick ~ชั่วโมง, (ค) ความลึกน้ำบนถนน (ซม.), (ง) หมวดคำเตือนของ
  หน่วยงานที่ถูกเล่าต่อ — **ไม่มีอันไหนคือบรรยากาศหรือน้ำ "ตัวจริง"** ทุกอันเป็น readout ที่มีความละเอียดและ
  หน้าต่างเวลา (collector เริ่มเก็บเมื่อไร = left-censoring).
- สิ่งที่ **ไม่ใช่ readout** ในงานนี้: สนาม PDE ต่อเนื่อง (h→0), ln/exp ใน Clausius–Clapeyron, geostrophic เป็นสมการ
  เท่ากับแบบแม่นตรง, "คาบการเกิดซ้ำ" ที่ไม่มีตารางเกณฑ์ถือไว้, แนวโน้มความกดอากาศ (คลังนี้ **ไม่มี** อนุกรมความกด
  เก็บไว้เลย — MEASURED: ตาราง `observations` ไม่มี variable ความกด).
- ชนิดปัญหา (ตั้งชื่อหลังโน้ต): equation-reuse + verification backtest; route `toledo` (TG-RFG-01),
  `information-discrete-math`, `readout_universe` (TIER-TAGGING).

## 3. Step 2 — แปลเป็นเลนส์สารสนเทศไม่ต่อเนื่อง (IDM)

กฎแปล 8 ข้อ (ทุกข้อเป็น **ทางเลือกเชิงวิธี — tier Dr/INSTINCT** เว้นแต่ระบุรหัส Th_coqc):

1. **Tick จำกัด** — เวลาเป็นจำนวนเต็มของ τ (ชั่วโมง หรือวัน) ที่ประกาศ; ไม่มี dt→0. ฝน 24 ชม. เป็นผลรวม 24 tick ไม่ใช่
   อินทิกรัล (discrete FTC `R/M.09.v1`, `A2/M.03.v1` — Th_coqc).
2. **เซลล์/โหนดจำกัด** — หน่วย = ลุ่มน้ำย่อย DWR, เขต, พื้นที่ปิดล้อมย่อย (sub-polder) 38 แห่งของ กทม., โหนดคลอง, จุด;
   ทุกหน่วยประกาศพร้อมแหล่ง. ระยะทางบนเครือข่าย = ผลรวมตามเส้นทางที่ดีที่สุด (min-plus `Z/M.21.v1`) ไม่ใช่ √Σ(Δx)².
3. **ทุกค่าที่อ่านมีความละเอียด ε** — มาตรวัดฝน 0.1 มม., ระดับคลอง 0.01 ม., ถนน 1 ซม.; ความละเอียดของ *การพยากรณ์*
   ไม่ใช่ ε ของเครื่องมือ แต่คือ **ความกว้างของช่วงข้ามโมเดล** (ข้อ 5).
4. **สามสถานะ** — เทียบกับเกณฑ์ θ: `v := (lo+hi)/2 − θ`, `floor := (hi−lo)/2` → `classify floor v ∈ {Sp, Sm, ⊥}`
   = เหนือแน่ (ROBUST) / ต่ำกว่าแน่ (BELOW) / ยังแยกไม่ได้ (POSSIBLE) — **REUSE `D/M.71.v1`–`D/M.76.v1`** (Th_coqc,
   renaming ตามเอกสาร reuse §4). ⊥ ไม่ใช่ "ปลอดภัย" และไม่ใช่ 0 (Genesis A.13 Gate 2: ⊥ = unresolved, do not guess).
5. **ช่วงจากหลายโมเดล — แย่สุดก่อน ไม่เฉลี่ย** — `I = [min_m x_m, max_m x_m]`; รายงาน `hi` ก่อน (REUSE 06 v6.1).
   โมเดลเดียว ⇒ ช่วงเสื่อม (lo=hi) และ **ความกว้างที่แท้จริงไม่รู้** → ต้องประกาศว่า "spread unknown" ไม่ใช่
   "แน่นอน" (ข้อเท็จจริงที่ backtest ชนเข้าจริง: previous-runs มีแต่ GFS).
6. **ไม่มี +∞, ไม่มี 0 ที่ถูกยึดครอง** — "ไม่เคยเกิด", "คาบไม่จำกัด", "Q_out = 0 ⇒ เวลาระบาย = ∞" ทั้งหมด = REFUSED
   (ไม่นิยาม) ไม่ใช่ตัวเลข. ค่า 0.0 จากมาตรวัดฝนที่ข้างเคียงได้ >100 มม. = readout ที่น่าสงสัย ไม่ใช่ "ฝนไม่ตก" (พบจริง
   3 เขตใน backtest — OPEN).
7. **ℚ-computable เท่านั้น** — ทุกพจน์ในชุดสมการเราเป็น +, −, ×, ÷, max, min บน ℚ; ไม่มี ln, √, ตรีโกณ, ยกกำลังเศษส่วน.
   นี่คือเหตุผลที่ Manning, Clausius–Clapeyron (รูป ln), geostrophic (sinφ), Saint-Venant ถูกปฏิเสธเป็น parent.
8. **ความสอดคล้องเมื่อ zoom** — ชั้นละเอียดต้องไม่พลิกเครื่องหมายที่ชั้นหยาบตัดสินแน่แล้ว เว้นแต่บันทึกเป็นแถวขัดแย้ง
   (REUSE `D/M.77.v1` bot_monotone_in_floor + เงื่อนไข nested box ซึ่งเป็น delta ที่ยังไม่ขึ้นทะเบียน).

### 3.1 NWP ในเลนส์เรา

ตัวโมเดลเป็น stepper แบบไม่ต่อเนื่อง `S_{n+1} = F(S_n, u_n, c_n, T_n)` อยู่แล้ว (รูปเดียวกับ `weld/M.01.v1` ส่วน stepper —
Dr). เรา **ไม่รัน F** (ไม่มีสถานะบรรยากาศ); เราอ่าน `Y_m(t_issue, t_target, cell)` จากหลาย agency m แล้ว:
(ก) ช่วงข้าม m, (ข) สามสถานะเทียบบันไดเกณฑ์, (ค) ติดป้าย horizon = t_target − t_issue (จำนวนเต็มวัน/ชม.).
