### สิ่งที่มี "public" จริง (VERIFIED, ดึงมาแล้ว)

**พบ 1 ชุดข้อมูลที่ตรงคำถามที่สุดในรอบสำรวจนี้**: `data.bangkok.go.th/dataset/drain-pipe`
("โครงข่ายท่อระบายน้ำ") — CSV **2,904 แถว** จาก สำนักการระบายน้ำ กทม. เอง (`sources/
api_census_drainage.yaml` id `bma_opendata_drain_pipe_csv`, เก็บตัวอย่างที่
`raw/live/bma_open_data_drainage_org/drain_pipe_full.csv`). โครงสร้าง:

| ฟิลด์ | ความหมาย |
|---|---|
| `DISTRICT_NAME` | เขต |
| `ROADCL_NAME` | ชื่อถนน/ตรอกซอยที่ท่อวางอยู่ |
| `PIPE_FROM` / `PIPE_TO` | จุดเริ่ม/จุดสิ้นสุด **เป็นชื่อถนน/ทางแยก** (topology จริง แต่เป็นชื่อ ไม่ใช่พิกัด) |
| `R_DIMENSION`/`R_LENGTH`/`R_TYPE` | ท่อฝั่งขวา: ขนาด(ม.)/ความยาว(ม.)/ประเภท (เช่น ท่อกลม) |
| `L_DIMENSION`/`L_LENGTH`/`L_TYPE` | ท่อฝั่งซ้าย เหมือนกัน |
| `ROAD_DIMENSION`/`ROAD_LENGTH`/`ROAD_TYPE` | ท่อ/รางระดับถนน (เช่น รางระบายน้ำ) |
| `PJ_DIMENSION`/`PJ_LENGTH`/`PJ_TYPE` | ท่อดันลอด (pipe jacking) |
| `PIPE_LENGTH` | รวมความยาว |

**ข้อจำกัดสำคัญ: ไฟล์นี้ไม่มีพิกัด (lat/lon) เลย** — ตำแหน่งอนุมานได้เฉพาะจากชื่อถนน/ทางแยกใน
`PIPE_FROM`/`PIPE_TO` เทียบกับ gazetteer ถนน (เช่น OSM) เท่านั้น ซึ่งเป็นการ geocode ใหม่ ไม่ใช่ของ
ในไฟล์เอง — **ไม่ทำในบัตรนี้** ตามกฎ "ไม่เดาพิกัดโดยไม่มีป้าย INSTINCT + ฟาวน์เดอร์อนุมัติ"

ชุดข้อมูลพี่น้อง `pipe_jacking` ("ระบบท่อขนส่งน้ำ (ท่อดันลอด)") มีอยู่ พบหน้าเพจ/ลิงก์ดาวน์โหลด
`data-pipe-jacking.csv` แต่ **ไม่ได้ดึงไฟล์จริง** รอบนี้ (RELAYED เฉพาะการมีอยู่ของชุดข้อมูล)

Portal `data.bangkok.go.th` (องค์กร "สำนักการระบายน้ำ") ยังมีชื่อชุดข้อมูลอื่นที่ไม่ได้เปิดดู:
`dike` (เขื่อน/คันกั้นน้ำ), `flood-prevention`, `flood_risk`/`flood_risk26` — ชื่ออาจเกี่ยวกับ
สินทรัพย์กายภาพเพิ่มเติม (ไม่ยืนยัน)

data.go.th (federated CKAN search, คำค้น "ท่อระบายน้ำ", 13 ผลลัพธ์) เจอ:
- **"ความพร้อมของระบบท่อระบายน้ำของกรุงเทพมหานคร"** — ชื่อเรื่องอย่างเดียว ไม่ได้เปิด (น่าจะเป็น
  ข้อมูลสถานะ/แผนงาน ไม่ใช่ geometry)
- **"แผนที่ท่อระบายน้ำ" / "ขนาดของท่อระบายน้ำ" ของสำนักงานจังหวัดนนทบุรี** — จังหวัดข้างเคียง กทม.
  ไม่ใช่ตัวเมืองเอง แต่เป็นตัวอย่างว่ามีจังหวัดไทยอย่างน้อยหนึ่งแห่งเผยแพร่ "แผนที่ท่อระบายน้ำ" บน
  data.go.th จริง — ควรตรวจดูว่าไฟล์นั้นมี geometry จริงหรือไม่ (ยังไม่ได้ตรวจ)

## แผนนำเข้า KG (ต่อคลองที่มีอยู่แล้ว)

**Node class ใหม่ที่เสนอ** (ยังไม่ implement — เสนอไว้ในบัตรนี้):

| class | มาจากไหน | มีพิกัดไหม |
|---|---|---|
| `drain_segment` | `bma_opendata_drain_pipe_csv` 1 แถว = 1 segment (ต่อถนน/ต่อฝั่ง R หรือ L) | ไม่มี — ต้อง geocode ผ่านชื่อถนน (ไม่ทำในรอบนี้) |
| `culvert` | `PJ_*` fields (pipe-jacking) ในไฟล์เดียวกัน, หรือ dataset `pipe_jacking` แยก | เหมือนกัน |
| `manhole` / `บ่อพัก` | ไม่พบแหล่งสาธารณะเลยรอบนี้ | OPEN |
| `sub_pump` | สถานีสูบน้ำย่อยของหมู่บ้าน (ไม่ใช่ของ กทม.) — ไม่มีแหล่งสาธารณะ, ต้องขอจากนิติบุคคลหมู่บ้านโดยตรง (ดูหัวข้อ Sammakorn ด้านล่าง) | OPEN |

**Edge**: `DRAINS_TO` (segment → segment → canal) — ตาม `PIPE_FROM`/`PIPE_TO` **เฉพาะกรณีที่แหล่ง
ข้อมูลระบุ topology ชัดเจนเท่านั้น** (ชื่อถนนตรงกับสอง segment ที่ติดกัน) — **ห้ามเดา snap ทาง
เรขาคณิต** โดยไม่มีป้าย INSTINCT + การอนุมัติจากฟาวน์เดอร์ ตามกฎของโปรเจกต์นี้ (`AGENTS.md` §2,
Toledo/epistemic floor) การเชื่อมต่อสุดท้ายจาก drain_segment ปลายทางเข้าสู่ node คลองที่มีอยู่แล้ว
(`canal`/`canal_node`) ก็ต้องอาศัยชื่อคลองที่ระบุตรงกัน ไม่ใช่ระยะทางใกล้ที่สุด

**ประมาณการแถว (INSTINCT, ยังไม่ verify)**: ถ้านำเข้า `drain_pipe.csv` ทั้งหมด (2,903 data rows)
เป็น `drain_segment` node หนึ่งแถวต่อหนึ่ง node (ไม่แยกฝั่ง R/L เป็นคนละ node) จะได้ประมาณ **~2,900
nodes ใหม่** — แต่หลายแถวมี `PIPE_FROM`/`PIPE_TO`/`ROADCL_NAME` ว่างเปล่า (ตัวอย่างที่เห็นในการอ่าน
ตัวอย่าง: แถวที่ 5, 7, 8, 10 ในตัวอย่างข้างต้น) ซึ่งจะเชื่อมต่อ topology ไม่ได้เลย — จำนวนที่เชื่อม
`DRAINS_TO` ได้จริงน่าจะ**น้อยกว่า 2,900 มาก** ยังไม่มีตัวเลขที่วัดจริง (OPEN)

**ขั้นตอนที่แนะนำก่อนนำเข้าจริง** (ไม่ได้ทำในบัตรนี้):
1. ตรวจนับแถวที่มี `PIPE_FROM`+`PIPE_TO` ครบทั้งคู่ (topology ใช้ได้จริง) เทียบกับแถวว่าง
2. ตรวจว่า `ROADCL_NAME`/`PIPE_FROM`/`PIPE_TO` ตรงกับชื่อถนนใน OSM ได้กี่ % (ถ้าจะ geocode ในอนาคต
   ต้องผ่าน INSTINCT tag + ฟาวน์เดอร์อนุมัติก่อน ตามกฎ)
3. ดาวน์โหลดและอ่าน `data-pipe-jacking.csv` จริง (ยังไม่ได้ทำรอบนี้)
4. ลอง Overpass ใหม่อีกครั้งด้วยฟอร์แมตคำขอที่ต่างออกไป หรือ endpoint อื่น (เช่น
   `overpass.private.coffee` หรือ `overpass.openstreetmap.fr`) เพื่อให้ได้จำนวน feature OSM จริง

ได้จริงมีทางเดียว: แผนผังท่อระบายน้ำภายในของนิติบุคคลหมู่บ้านสัมมากรเอง** (community-supplied
source) ซึ่งเป็นข้อมูลที่ **ไม่มีใครนอกหมู่บ้านเข้าถึงได้** จนกว่าจะมีคนขอจากนิติบุคคลโดยตรง — นี่คือ
"community-supplied" ระดับเดียวกับที่ AGENTS.md เรียกร้องให้ project นี้แยกจาก official/RELAYED
tag ให้ชัด: ถ้าได้แผนผังนั้นมาจริง จะต้อง tag **RELAYED (community, ไม่ตรวจสอบทางเทคนิคเอง)**
ไม่ใช่ VERIFIED ตราบใดที่ไม่มีการรังวัดยืนยันเอง — และควรบันทึกที่มา (ใครในนิติบุคคลเป็นผู้ให้ วันที่
ให้) โดย**ไม่ใส่ชื่อบุคคล**ตามกฎ "No personal names" ของ repo นี้ (บันทึกเป็นตำแหน่ง เช่น
"นิติบุคคลหมู่บ้านสัมมากร" ก็พอ)
